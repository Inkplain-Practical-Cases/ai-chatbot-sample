# CDAF(TM) -- Canvas Driven Architecture Framework
## Python / FastAPI Variant - Engineering & Code Standardization Guide
**Version:** 1.0-python - **Based on:** CDAF(TM) v1.0 by Anar Rustamov (DPS Alliance)
**Website:** https://dpsummary.com

> This is the backend/Python translation of `A1. CODEBASE_STRUCTURE.md` (Next.js variant).
> UI-only concepts (React Query, Server Components, i18n messages, fonts, emoji rules) do not
> apply to a Python backend and are dropped. Everything about **ownership boundaries**,
> **one-operation-per-file**, and **thin door / handler / service** layering is preserved.

---

## 1. Core Principle

```
One Feature Package = One Business Capability = One Router = One Service Layer
```

Each business capability (auth, ingestion, chat, retrieval, tools) is organized as a
**feature package** (`feature_<name>/`). Every feature is architecturally isolated and
operates as a fully independent unit -- it does not import another feature's internals.

---

## 2. Feature Map (this project)

| Capability          | Feature Package        | Router                | Owns                                   |
|----------------------|-------------------------|------------------------|-----------------------------------------|
| Auth                 | `feature_auth`          | n/a (used as a dep)   | JWT decode/verify                       |
| Ingestion            | `feature_ingest`        | `/ingest` (optional)  | PDF -> text -> chunk -> embed -> Chroma |
| Chat / WebSocket     | `feature_chat`          | `/ws/chat`             | WS protocol, streaming, RBAC retrieval  |
| Employee Tool        | `feature_employee_tool` | n/a (LLM tool)         | parallel `get_employee_context`         |

> [!] A global "do everything" `main.py` with business logic inline is **strictly forbidden**.
> `main.py` only assembles the FastAPI app and includes routers.

> [!] **Strict Rule:** Importing `features/feature_chat/services/` from inside
> `features/feature_ingest/` is **forbidden**. Shared logic (e.g. a Chroma client
> singleton) belongs in `providers/`, not in another feature.

> [OK] **Documented exception:** `feature_employee_tool` has no router of its own — it

> analogous to A1's "documented common/public infrastructure" exception. `feature_chat`

> alone. A feature with its own router must still never import another feature's
> `services/`/`handlers/` directly.

## 4. Provider Governance (replaces QueryClient Governance)

```python
# providers/llm/base.py
from typing import Protocol, AsyncIterator

class LLMProvider(Protocol):
    async def stream_chat(self, messages: list[dict], tools: list[dict] | None = None) -> AsyncIterator[str]:
        ...
```

**Rules:**
- One concrete provider is selected **once**, at startup, via `core/config.py` (env var, e.g. `LLM_PROVIDER=groq`).
- Features depend on the `LLMProvider` / `EmbeddingProvider` / `VectorStore` **interface**, never on a concrete class directly.
- Dynamic provider construction inside a request handler is **forbidden** -- build it once (e.g. via `functools.lru_cache` dependency) and inject with `Depends(...)`.
- Cross-feature provider re-instantiation is **forbidden** -- reuse the shared singleton from `providers/`.

## 4a. Comment Standard (Python-specific)

Every file must open with a 1-2 line comment stating **what the file is responsible for**
and, if relevant, **what layer calls it / what it calls**. Every non-trivial function gets
a short docstring or inline comment explaining its role in the request flow (auth step,
message loop, RBAC filter, parallel tool call, etc.) -- not a restatement of the code, but
the *why*/*role* a reader would otherwise have to infer from call sites.

```python
# Orchestrates the whole /ws/chat lifecycle: accept -> auth handshake ->
# message loop -> stream reply. Called by router.py, never called directly
# by a route (keeps router.py a thin door).
from fastapi import WebSocket, WebSocketDisconnect
```

**Rules:**
- File-level comment: 1-2 lines, at the very top, above imports.
- Function/class docstring: only when the name alone doesn't make the role obvious (e.g.
  a Pydantic model representing one specific wire-protocol message).
- Step comments inside a handler (e.g. `# Step 1: auth handshake`) are encouraged for
  multi-stage flows (auth -> retrieval -> LLM -> stream) so the flow reads top to bottom.
- Do not restate what a line already says (`i += 1  # increment i` is forbidden).
- This applies to every file from here on, including future features (`feature_ingest`,
  `feature_employee_tool`, `providers/`).

## 5. Dependency Injection Pattern (replaces Layout & Provider Pattern)

The FastAPI equivalent of the Next.js `layout.tsx` injecting a `QueryClient` is a
**dependency provider function** injected with `Depends()`.

```python
# core/dependencies.py
from functools import lru_cache
from app.providers.vectorstore.chroma_store import ChromaStore

@lru_cache
def get_vectorstore() -> ChromaStore:
    return ChromaStore(path=settings.chroma_path, collection_name=settings.chroma_collection)
```

```python
# features/feature_chat/router.py
from fastapi import Depends
from app.core.dependencies import get_vectorstore

@router.websocket("/ws/chat")
async def chat_socket(websocket: WebSocket, store = Depends(get_vectorstore)):
    await handle_chat_socket(websocket, store)
```

> [!] Business logic must never live directly in the `@router` function body beyond
> unpacking dependencies and delegating to a handler -- same "thin door" rule as Next.js `route.ts`.

## 6. Router & Handler Pattern (replaces Page & Canvas Pattern)

### Rule: `router.py` is a Door -- Not a Handler

`router.py` declares the route and its dependencies, then calls exactly one handler.
It must contain **zero business logic**.

```python
# features/feature_chat/router.py
from fastapi import APIRouter, WebSocket, Depends
from app.features.feature_chat.handlers.handle_chat_socket import handle_chat_socket
from app.core.dependencies import get_vectorstore, get_llm_provider

router = APIRouter()

@router.websocket("/ws/chat")
async def chat_socket(
    websocket: WebSocket,
    store=Depends(get_vectorstore),
    llm=Depends(get_llm_provider),
):
    await handle_chat_socket(websocket, store, llm)
```

All logic (auth handshake, message loop, retrieval, streaming, error handling) lives inside
`handlers/handle_chat_socket.py`, which in turn delegates to `services/`.

### Folder Mapping: Router -> Handler -> Service

```
features/
  feature_chat/
    router.py                          <- thin door: declares /ws/chat
    handlers/
      handle_chat_socket.py            <- orchestrates the whole WS lifecycle
    services/
      service_retrieve_chunks.py       <- one job: RBAC-filtered Chroma query
      service_stream_llm.py            <- one job: call LLM, yield tokens
```

**Rules:**
- Every feature folder must be named `feature_<name>`
- `router.py` = route declaration + dependency wiring only, nothing else
- `handlers/handle_<flow>.py` is the orchestration entry point (equivalent of `{Page}Canvas.tsx`)
- `services/service_<job>.py` does exactly one job (DB call, external API call, pure computation)
- A service must **not** import another feature's handler or service directly

## 7. Async & Blocking Call Discipline (Python-specific, replaces Server/Client Component Strategy)

| Layer            | Rule                                                                 |
|-------------------|-----------------------------------------------------------------------|
| `router.py`       | `async def` always, no blocking calls                                |
| `handlers/`       | `async def` always, orchestrates concurrently with `asyncio.gather`  |
| `services/`       | `async def` for I/O (DB, HTTP, WebSocket); `def` only for pure CPU logic |
| CPU-bound work    | (e.g. OCR, embedding a large batch) must run via `asyncio.to_thread(...)` or a worker, never inline in an `async def` request path |

```python
# tool_get_employee_context.py -- the parallel tool call required by the assignment
import asyncio

async def tool_get_employee_context(user_id: str) -> dict:
    profile, manager, team = await asyncio.gather(
        service_get_profile(user_id),
        service_get_manager(user_id),
        service_get_team(user_id),
    )
    return {**profile, **manager, **team}
```

> [!] `asyncio.gather` (not sequential `await`) is what makes total elapsed time ~1s, not ~3s.
> This directly satisfies Requirement 5 in the assignment README.

## 8. RBAC-at-Query-Layer Governance (Python-specific, replaces Server Actions)

RBAC filtering happens **inside the vector store service**, never as a Python-side
post-filter over already-returned results.

```python
# providers/vectorstore/chroma_store.py
# Chroma's `where` clause supports $and/$or/$lte directly -- no separate
# filter-builder object is needed like Qdrant's Filter/FieldCondition.
def query(self, query_embedding, department: str, level: int, limit: int = 5):
    where_filter = {
        "$and": [
            {"$or": [{"department": department}, {"department": "hr"}]},
            {"access_level": {"$lte": level}},
        ]
    }
    return self._collection.query(
        query_embeddings=[query_embedding],
        n_results=limit,
        where=where_filter,
    )
```

```python
# features/feature_chat/services/service_retrieve_chunks.py
async def service_retrieve_chunks(query_embedding, user, store) -> list[Chunk]:
    # store.query() is sync (Chroma's local client has no async API) -- run it
    # off the event loop so it never blocks other connections' message loops.
    return await asyncio.to_thread(store.query, query_embedding, user.department, user.level, 5)
```

> [OK] The filter is a `should` of two `must` blocks: "own department" OR "hr" -- both capped
> by `access_level <= user.level`. This is the "cleanest way to express" the HR exception
> called out in Requirement 3.
> [!] A service that fetches unfiltered results and filters them in a Python list comprehension
> is a **rubric violation** -- do not do this, even temporarily "to get it working."

## 9. File Naming -- CDAF Python Standard

| Layer          | Prefix          | File Example                     | Export Example                              |
|-----------------|------------------|-----------------------------------|-----------------------------------------------|
| Routers        | `router`         | `router.py` (one per feature)     | `router = APIRouter()`                       |
| Handlers       | `handle_`        | `handle_chat_socket.py`           | `async def handle_chat_socket(...)`          |
| Services       | `service_`       | `service_retrieve_chunks.py`      | `async def service_retrieve_chunks(...)`     |
| Providers      | `<name>_provider.py` / `<name>_store.py` | `groq_provider.py`  | `class GroqProvider(LLMProvider)`            |
| Schemas        | `_schemas.py`, PascalCase classes | `chat_schemas.py`  | `class ChatMessage(BaseModel)`               |
| Utils          | `util_`          | `util_format_page.py`             | `def util_format_page(...)`                  |
| Tools (LLM)    | `tool_`          | `tool_get_employee_context.py`    | `async def tool_get_employee_context(...)`   |

**Golden Rule -- 1 File = 1 Export**

Every function, class, or Pydantic model that represents one unit of behavior lives in its
own file. The file name must reflect the exported entity's purpose (snake_case of its name).

## 10. The Correct CDAF Chain (Python)

```
Router (thin door)
  -> Handler (handle_xxx)         [orchestration, async]
    -> Service(s) (service_xxx)   [one DB/API/computation job each, run concurrently where independent]
      -> Provider (LLM / VectorStore / Embeddings)
```

Example -- the chat flow end to end:

```
WebSocket /ws/chat
  -> router.py (declares route, injects store + llm provider)
    -> handle_chat_socket.py
      -> service_verify_jwt.py            (auth message)
      -> service_retrieve_chunks.py       (RBAC-filtered Chroma search)
      -> service_stream_llm.py            (streams tokens back over the socket)
      -> tool_get_employee_context.py     (only if the LLM calls the tool)
```

## 11. Forbidden Patterns

| Forbidden                                                        | Reason                                   |
|--------------------------------------------------------------------|--------------------------------------------|
| Business logic inside `main.py`                                   | Violates Router & Handler pattern          |
| Business logic inside `router.py` beyond dependency wiring         | Violates thin-door rule                    |
| Blocking I/O (`requests`, sync file/OCR calls) inside `async def`  | Blocks the event loop, breaks concurrency  |
| Sequential `await` for the 3 employee-context calls                | Fails the ~1s parallel requirement         |
| Post-filtering Chroma results in a Python list comprehension      | RBAC must be enforced at the DB layer      |
| A feature importing another feature's `services/` directly        | Breaks feature isolation                   |
| Concrete provider class referenced outside `providers/` and DI    | Breaks pluggability requirement            |
| More than 1 exported function/class per file                      | Violates 1 File = 1 Export rule            |
| Hardcoded JWT secret / API keys in source                          | Must come from `.env` via `core/config.py` |

## 12. Standard of Acceptance (Python)

A contribution is accepted when it:

- [OK] `main.py` only builds the app and includes routers
- [OK] Every route is a thin door delegating to exactly one handler
- [OK] Every service does exactly one job and is `async` for I/O
- [OK] LLM / Embeddings / VectorStore are used only through their `providers/` interface
- [OK] RBAC filter (`department == user.department OR department == "hr"`, `access_level <= user.level`) is built inside the vector store query, never post-filtered
- [OK] The employee-context tool uses `asyncio.gather`, verified to run in ~1s
- [OK] No blocking calls exist inside any `async def`
- [OK] Pydantic models are used for every WebSocket message in/out
- [OK] Type hints are present on all public functions
